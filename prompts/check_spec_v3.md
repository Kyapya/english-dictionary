# check_spec_v3

このファイルは、生成直後の記事およびユーザーが指定した既存記事を、独立した視点でチェック・修正するための現行仕様である。
Codexはチェックを始める前に、必ずこのファイルと `prompts/entry_spec_v3.md` を最初から最後まで読むこと。

## 適用原則

- 生成後の自動チェックとユーザー指示による個別チェックで、チェック品質、確認観点、本文修正ルールに差を付けない。
- 生成時の自己確認を、独立チェックの代わりにしてはならない。
- 直前の生成結果や既存本文の項目構成を完全と仮定しない。
- 形式検査に通ることと、内容チェックに通ることを混同しない。
- チャット応答の分割やNotion保存ではなく、保存されるMarkdown完成版の内容と品質を確認する。

## チェック対象

- 生成直後のMarkdown辞書記事。
- ユーザーが指定したMarkdown辞書記事。
- ユーザーが1箇所だけ指摘した場合も、同種の誤りや漏れが記事全体にないか確認する。

## チェックの二段階

チェックでは、次の2工程を分けて行う。

1. 既存本文の校正。
2. 見出し語のゼロベース棚卸し。

「ゼロベース」とは旧本文を見ないことではなく、旧本文に書かれた語義・構文だけを候補集合にしないことを意味する。

## 既存本文の校正

次の正確性と自然さを確認する。

- 定義、中心訳、ニュアンス、含意、話者評価、暗黙の前提。
- 例文と訳の一致、自然さ、現代性、主語・目的語・状況設定。
- コロケーション、構文、自他、目的語位置、前置詞、小辞、補語、能動・受動、否定・疑問、時制。
- 冠詞、可算・不可算、単複、限定・叙述、品詞転換。
- 類義語の定義、重なり、違い、例文、頻度。
- 反意語が同じ意味軸上にあるか、解決策・結果・原因・関連概念を誤って含めていないか。
- 地域差、レジスター、専門性、古風性、頻度スコア。
- 語源、語形成、同語源語、コアイメージ。
- 見出し順、固定行数、空行、半角スペース2個、裸語禁止、例文配置、完成版への `【続きあり】` 混入などの形式。

## ゼロベースの網羅性確認

`entry_spec_v3.md` の「出力前の内部確認」と同じ水準で、次を再実行する。

1. 根拠確認。
2. 語義棚卸し。
3. 構文棚卸し。
4. 語義と構文の対応づけ。
5. 網羅性マトリクス。
6. 棚卸しと本文の双方向照合。

特に次を確認する。

- 主要品詞、同一品詞内の主要義、自他差、可算・不可算、字義・比喩・慣用義。
- 非合成的句動詞、前置詞動詞、句前置詞動詞、目的語位置や後続前置詞で意味が変わる構文。
- 人・物目的語、主語種類、分離可能性、代名詞位置、受動、分詞形容詞、補文。
- 短いフレーズの固定性、置換可能性、語順、時制・人称・数、否定・疑問、要素省略、単独発話。
- 米英差、地域差、レジスター差、一定頻度の専門義、定型的な低頻度用法。
- 同綴異義語、固有名詞、略語、活用形・派生形との関係。
- 重要構文が `【文法パターン】` と `【コロケーション】` の両方に対応しているか。
- 低頻度用法の説明量が主要用法を上回っていないか。

## 項目数と説明量の確認

- 類義語は原則3～8語、使い分けが重要なら10語程度までという基準に照らし、主要な比較対象の不足や冗長な水増しがないか確認する。
- 反意語は同一意味軸上の語を原則2～6語という基準に照らし、不適切な関連概念の混入がないか確認する。明確な反意語がなければ欄の省略を認める。
- コロケーションは各語義について原則4～10件という基準に照らし、主要構文、定型表現、誤用しやすい結合、重要な使い分けが例文付きで収録されているか確認する。
- 原則件数を機械的な合格条件にしない。実在する重要項目が多ければ上限を超えても削らず、適切な項目が少なければ件数合わせをしない。
- 項目数を増やすための自由結合、同義反復、差の乏しい近義語、意味軸の異なる反意語、根拠の乏しい周辺用法が含まれていないか確認する。
- 定義、主要構文、自然な使用場面、誤用ポイント、重要な近義語との差が、学習者が実際に理解・運用できる粒度で説明されているか確認する。
- 棚卸しで確認した独立した学習価値のある情報に本文内の収録先がなければ、形式上すべての欄が存在していても内容不足として修正する。

## 旧本文と独立棚卸しの比較

次の差を明示的に確認する。

1. 旧本文だけにある誤用・不自然な用法。
2. 独立棚卸しだけにある重要な欠落。
3. 語義・構文の不適切な統合。
4. 同一語義の過剰な細分化。
5. 例文、構文、語義、レジスターの不一致。
6. `【文法パターン】` と `【コロケーション】` の不一致。
7. 語義番号、頻度順、コアイメージの派生マップ、相互参照の不整合。

## 修正ルール

- 誤り、重要な欠落、形式不備があれば、記事ファイルへ修正版全文を反映する。
- 差分だけを提示・記録して、記事本文を未修正のままにしてはならない。
- 修正しない箇所は不用意に変えない。
- 語義の追加・統合・分割に伴い、番号、頻度順、コアイメージ、文法パターン、コロケーション、相互参照の整合に必要な範囲は修正する。
- 反意語の意味軸が不明瞭なら、無理に別の関連概念へ置換せず欄を省略する。別項目を水増しして埋め合わせない。
- 修正後はfront matterの `updated_at` と `prompt_version: entry_spec_v3` を更新する。
- 修正後に `scripts/validate_entry.py` を再実行する。
- 修正が完了し、内容確認が残らなければ front matter の `status: checked`、`checked: true`、queueのstatusを `checked` にする。
- 内容確認が残る場合は front matter の `status: needs_review`、`checked: false`、queueのstatusを `needs_review` にする。
- 修正内容は日付付きlogsに、何を追加・削除・統合・分割・訂正したか分かる粒度で記録する。

## 修正不要の場合

- 記事本文は変更しない。
- v3基準を満たすことを確認した記事だけ、front matterとqueueの `prompt_version` を `entry_spec_v3`、statusを `checked`、checkedを `true` にする。
- logsに「修正不要」と明記する。
- 自動チェックでもユーザー指示チェックでも同じ扱いとする。

## チェック完了条件

- `entry_spec_v3.md` の品質基準と形式を満たしている。
- 主要語義と主要構文に本文内の収録先がある。
- 各語義の中心用法を示す見出し語自身の例文がある。
- 定義、例文、訳、文法パターン、コロケーションが相互に一致している。
- 類義語の違いが具体的な比較軸で説明され、原則件数から外れる場合も不足または水増しになっていない。
- 反意語が同じ意味軸上にあり、不適切な場合は欄が省略されている。
- コロケーションが主要構文を具体化し、原則件数から外れる場合も不足または水増しになっていない。
- 独立した学習価値のある重要情報に収録漏れがなく、同義反復や件数合わせによる水増しもない。
- 不確かな語源、地域差、頻度を断定していない。
- 保存本文にチャット固有の前置き、締め、次回予告、`【続きあり】` がない。
- `scripts/validate_entry.py` が終了コード0で通る。
- front matter、queue、logsが同期している。
