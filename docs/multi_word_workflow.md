# 1語・複数語の通常作業

1語でも複数語でも `AGENTS.md` と同じ **作成 → 独立点検 → 必要箇所修正** を使う。
単語一覧をユーザーにCLIへ書き直させず、担当者が対象を整理する。

```sh
python scripts/start_words.py alpha beta "take off"
python scripts/start_words.py --words-file words.txt
```

引数1つを1項目として扱う。カンマ・読点・改行でも区切れるが、空白だけでは
単語列とフレーズを機械判定しない。ファイルは1行1項目、または文字列のJSON配列。
コマンドは対象パスと手順を表示するだけで、queueの状態、記事、監査runを変更しない。
一覧外の語を追加しない。既存の同一語規則（大文字小文字・アポストロフィ・
空白とハイフンの違い）は維持する。それ以外で同じslugへ衝突する表記は
エラーとして扱い、別語を勝手に統合しない。

各語について最新mainと既存記事・作業branchを確認し、同じ語を重複作業しない。
既存記事は重複作成せず、依頼範囲に従って修正する。作成・点検・未解決の状態は
語ごとに扱い、一語の未解決を理由に他語の完成を取り消さない。

通常は逐次処理でよい。並列処理する場合だけworkspaceを分離し、同じ記事や
queue行を複数担当が同時に更新しない。公開前に最新mainとqueueの差分を照合する。
別の受付票、job台帳、監査予算、固定数のサブエージェントは通常作業に不要。
公開時の注意は `docs/multi_word_publication.md` を参照する。

旧queue/jobを明示的に再開する場合だけ `start_words.py --legacy ...` と
`docs/legacy_multi_word_workflow.md` を使う。通常工程との二重運用にしない。
