# check_spec_v1

このファイルは、既存の辞書記事をチェック・修正するための仕様である。
Codexは辞書記事をチェックする前に、必ずこのファイルを読むこと。

## チェック対象

直近に作成されたMarkdown辞書記事、またはユーザーが指定したMarkdown辞書記事を対象にする。

生成直後の記事は、ユーザーが別途依頼しなくてもこの仕様で自動チェックする。

## チェック方針

- 生成後の自動チェックとユーザー指示による個別チェックで、チェック品質・確認観点・本文修正ルールに差を付けない。
- 第三者のネイティブスピーカーの視点で、英語説明・例文・訳・コロケーション・類義語・反意語の妥当性を確認する。
- 学習者にとって説明が不足していないか確認する。
- 過剰説明、誤解を招く説明、頻度スコアの不自然さを確認する。
- 語源、地域差、古風な用法など、不確かな情報が断定されていないか確認する。
- 主要語義が1つにまとめられすぎていないか確認する。
- 比喩義、専門領域の重要義、宗教・法律・医学・ITなどの領域限定義、重要な固定表現が漏れていないか確認する。
- 見出し語に複数の主要語義がある場合、語義番号を分けて説明されているか確認する。
- 低頻度・文語的・専門的な語義でも、現代英語の理解や読解で重要なものが適切なラベル付きで扱われているか確認する。
- 指定フォーマットを確認する。
- 半角スペース2個が必要な箇所、ブロック間の空行、見出し順、類義語・反意語の6行固定、コロケーションの4行固定を確認する。

## 修正ルール

- 修正箇所がある場合は、記事本文を直接修正する。
- 修正しない箇所はなるべくそのまま保持する。
- 修正後、front matterの `updated_at` を更新する。
- チェック済みなら `checked: true` にする。
- queueのstatusを `checked` または `needs_review` に更新する。
- 修正内容は logs/ に記録する。

## 修正不要の場合

- 本文は変更しない。
- queueのstatusを `checked` に更新する。
- logs/ に「修正不要」と記録する。

## 生成後自動チェックの場合

- 形式検査に通った記事を対象にする。
- 修正不要または修正完了の場合、front matter の `checked` を `true` にし、queueのstatusを `checked` に更新する。
- 内容確認が残る場合、front matter の `checked` は `false` のままにし、queueのstatusを `needs_review` に更新する。
- 自動チェックの結果は logs/ に記録する。
