## Notion upsertと標準フローの自動化

- 同じ `ALL` のNotionページがない場合は新規作成し、1件ある場合はページIDと利用者管理プロパティを維持して本文だけを最新版へ置換するupsertへ変更した。
- 更新は新本文の追加成功後に旧本文ブロックをNotion API `2026-03-11` の `in_trash` でゴミ箱へ移す順序とし、アップロード失敗時に旧本文が失われないようにした。
- 同じ `ALL` のページが複数ある場合は、誤ったページを選ばず同期を失敗させるようにした。
- `--existing-policy update|skip|error` を追加し、既定値を `update` とした。従来の `--skip-existing` と `--no-skip-existing` は互換オプションとして維持した。
- Notion同期ワークフローは `--existing-policy update` を明示して、マージされたMarkdownを正本として反映するようにした。
- 標準フローを、PRの機械検証成功後にマージし、Notion同期成功まで確認する運用へ更新した。ユーザーがレビュー待ちを明示した場合だけ未マージで停止する。

## 同一見出し語のNotion保存方針変更

- 利用者の指定により、同じ `ALL` のページを更新するupsertを標準動作から外し、Notion同期のたびに新規ページを作成する方式へ変更した。
- GitHubでは同じ見出し語のMarkdownを最新版へ上書きし、Notionでは過去ページを変更・削除せず、新しい解説を `Status=未着手` の別ページとして保存する。
- `--existing-policy` の既定値と同期ワークフローの明示値を `create` に変更した。`update`、`skip`、`error` は手動実行用の選択肢として維持した。
